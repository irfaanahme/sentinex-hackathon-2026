Updated 18 October 2026 (Asia/Kolkata). This is a reconstructed account of the discussions, decisions, work and checks recorded in this project through that date. It is not a verbatim chat transcript. Dates below are precise where a portal status, file or note recorded them; otherwise the order reflects the conversation. For the current position, start with [STATE.md](STATE.md) and [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md). ## 1. Choosing the entries and setting up a handoff

- The team is SENTINEX (`TEAM-001130`), with Aswini Lakshya as portal owner/PPT leader and Irfaan Ahmed as the other recorded member. The event was the Talent AP Mega Hackathon 2026 at ANITS.
- The project reviewed the event page, signed-in portal, twelve problem statements, supplied documents and available portal information. Problem 11 (smart data masking) remained the primary choice. Problem 9/H4 (medication safety) replaced an earlier Problem 7/H2 discharge-plan idea as the second choice; R2 returns fraud remained an alternative. The reasoning was that masking and reference-backed medication checks offer observable tests, while a plausible-looking translated care plan could omit important instructions. This was a judgment about feasible scope, not a claim about odds of winning.
- Early working descriptions, technical concepts and teammate-facing rationale were saved in [DECISION_REPORT.md](DECISION_REPORT.md), the two Word reports and track `CONTEXT.md` files. Some of these describe proposals that were later superseded. The proposed MaskGate database pair was PostgreSQL and SQLite; the implemented pair became SQLite and DuckDB.
- The user requested a public, cross-device repository. An initial 149-file handoff included the proposal decks, reports, official templates, references, decisions and working archives, plus [HOME_START.md](HOME_START.md) and [STATE.md](STATE.md). Private attachments, identity documents, credentials and dependency caches were excluded. Git changes require an intentional commit and push; a local save is not synchronization.
- The official statements for Problems 9 and 11 linked to a seven-slide submission template. A separate six-slide template carried additional PDF, no-pre-built-code, CPU, supplied-data/model and kickoff-repository language. Which of those rules applies to these two entries has not been resolved. The team prepared seven-slide decks, without treating the discrepancy as permission to bring advance code to the finale.

## 2. From planned demonstration to two video prototypes

- The initial Problem 11 slide explicitly said **planned demo — prototype not yet built**: scan an approved synthetic table and inspect tags; run an approved query as Admin, Support and Analyst; repeat on two backends; reject a forbidden request; verify originals. Proposed evaluation included scanner precision/recall, role-policy pass rate, source equality and latency. These were plans, not measured results at that point.
- The user showed the official “Demo & POC Video” slide and asked for videos for both Problems 9 and 11. Two quick local prototypes were built for recording. These were distinct from the later working apps in [`apps/`](apps/); their source is retained in [`demo-prototypes/`](demo-prototypes/).
- For the medication prototype, four fictional medicines and illustrative rules were used. It demonstrated name resolution, interaction/duplicate/renal/contraindication warnings and uncertainty, with a clinician making the decision. It did not use the promised official H4 medicine and interaction references or prove clinical safety.
- For the masking prototype, the two actual engines were SQLite and DuckDB. It demonstrated field scanning, role-dependent output, rejection of raw SQL/role overrides and unchanged source snapshots. It was a narrow approved-query demonstration, not a general database security layer.
- The small prototype fixtures produced 144/144 MaskGate policy assertions, scanner precision 88.9% and recall 100% on 14 labeled field examples, plus source equality on both engines. The medication fixture produced 8/8 name-resolution checks and 3/3 serious issue detections, with no unexpected alerts in four handcrafted cases. These are **demo-fixture measurements**, not official hidden-set, real-world, or clinical performance.

## 4. Applications submitted and work broadened

- The signed-in InnoSmart portal later showed both applications **SUBMITTED** on 17 October 2026: H4/MedSafe `APP-20261017-0266` and data masking/MaskGate `APP-20261017-0267`. The portal confirmed the team's entries, not whether the organizer had watched the Drive clips. The submitted files remain fixed; later repository edits cannot alter those uploads.
- The user then asked for genuinely useful applications rather than video-only prototypes or placeholder buttons. They preferred **local apps first**, followed by free hosting if the workflows proved viable. The implemented code is in [`apps/`](apps/), with installation and operation notes in [apps/README.md](apps/README.md) and [apps/HOSTING.txt](apps/HOSTING.txt).
- Public/synthetic data were chosen over invented claims of a custom 20,000-record source: UCI Bank Marketing (45,211 records) for MaskGate and MITRE Synthea April 2020 sample data (1,171 synthetic patients and 42,989 medication rows) for MedSafe. Source URLs, licenses/attribution and hashes are in [`apps/datasets/sources.json`](apps/datasets/sources.json). UCI Bank Marketing is useful for scale and workflow testing but is **not a labeled PII-detection benchmark**. No real patient or customer records were uploaded. Five Synthea medication rows have stop-before-start dates; they were retained and excluded from active-review calculation.
- MaskGate became a persistent CSV-import and role-policy app using SQLite and DuckDB: scanning suggestions, administrator approval, password accounts, server-side Admin/Support/Analyst views, pagination/filtering, masked export, activity logging and integrity checks. It does not yet attach to an existing bank database or support arbitrary SQL rewriting.
- MedSafe became a Synthea import and medication-reconciliation app: patient search, dated review, repeated-code and ingredient overlap flags, NLM RxNorm ingredient lookup, reviewer notes and report snapshots. It has **no validated interaction, renal-dose, pregnancy or allergy rule set**. A clean review screen is not a clinical safety clearance.
- Local workflow/browser checks were run, then 16 workflow tests and 19 security/deployment tests passed before hosting. These finite checks do not prove a bug-free interface, universal masking or clinical effectiveness.

## 5. Privacy/security work and free hosting

- The user asked how a friend could try the apps and then requested a free hosted option with very high privacy and security. PythonAnywhere's free tier was selected for one site with separate `/medsafe/` and `/maskgate/` routes and persistent storage. The user created the account and enabled the necessary Chrome upload access. Both apps were installed at [MedSafe](https://iamirfaanahmed.pythonanywhere.com/medsafe/) and [MaskGate](https://iamirfaanahmed.pythonanywhere.com/maskgate/).
- The pre-hosting security pass addressed session replay, account-throttle reset and restricted-user digest exposure. The deployed code uses server-side revocable sessions, idle/absolute expiry, request budgets, CSRF/origin controls, HTTPS-only cookies in hosted mode, security headers, disabled public owner bootstrap and privacy/account pages. These measures materially improve the test deployment, but **“Apple-level” privacy and zero bugs were not established**. Databases are plaintext at rest in a shared hosted test workspace; use public/synthetic records only. Further work includes stronger isolation, MFA/passkeys, encrypted backup/restore, deletion controls and continuing review.
- The free site showed renewal due **18 November 2026**. Its test data were initialized privately; the user created owner credentials directly in the provider console. A proposed password reset was cancelled at the user's direction, leaving their chosen credentials unchanged. No plaintext credentials belong in this repository.
- On 18 October, public pages loaded over HTTPS, unauthenticated data endpoints denied access, and signed-in checks exercised MedSafe patient review and a MaskGate Admin query. Restricted-role behavior on the hosted imported dataset was not fully rechecked after admin policy review. NLM provider connectivity was checked, but ongoing availability is not guaranteed.

## Focused offline B1 build — 29 October 2026

The user narrowed the task to the supplied B1 dataset, exact coding guidelines and a strong, explainable competition demonstration. They confirmed the event machine will be another Mac. A separate local `maskgate-finals/` repository now implements real SQLite and PostgreSQL access to all nine source tables. It includes reviewed role policies, keyed pseudonyms, whole-cell text/JSON protection, read-only source verification and actual measured evidence. It is a new finals build; the older CSV-import SQLite/DuckDB app remains historical.

Final checks passed: 130 Python tests and 10 subtests, frontend lint/format, three dependency audits, 54,190 policy-related assertions and 83 cross-backend comparisons. Scanner development score is 98.75% precision / 100% recall against team-authored labels; branch opening date is one conservative false positive. Initial recall was lower for personal dates; the generic date rule was improved and measured on the same development labels, not a hidden set. All 129,260 rows were unchanged on both backends.

A source security review found rendered Admin query data could survive logout. The browser now discards the document at account transitions and notifies other tabs. Real same-tab Admin-to-Support and cross-tab logout checks passed. Delayed-response/forced-expiry browser races and production concurrency were not simulated. Local files remain unencrypted by the app.

The new L1 deck is in the outer deliverables directory as `MaskGate_B1_FINALS.pptx`; the finals code contains portable Mac setup and a five-minute judge explanation. The other Mac has not been tested yet. The code ZIP must retain .git (explicit organizer checklist) and exclude data/DBs/secrets/dependencies.
